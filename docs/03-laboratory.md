# Лабораторная работа: UI-тесты для Testboard

- **Тип:** Лабораторная работа
- **Максимальный балл:** 15

## Цель

Напишите UI-тесты на JavaScript и Playwright для двух задач: продавец публикует объявление, а посетитель сайта сохраняет и удаляет объявления в избранном.

## Сценарии для автоматизации

Всего 10 тестов, по пять в каждой части. Для каждого теста используйте новый контекст браузера.

### Часть 1. Добавление объявления

**Позитивный сценарий.** Войдите продавцом через фикстуру `authedPage`. Через форму опубликуйте объявление с уникальным названием, описанием, ценой, количеством и фотографией. В одном тесте проверьте весь путь:

- В профиле откройте «Мои объявления». Найдите карточку по точному названию и сверьте её ID с ID из ответа на публикацию.
- В каталоге введите полное название в строку поиска. В выдаче должна появиться карточка с тем же ID.
- Откройте карточку из выдачи. Название, описание, цена и количество совпадают с введёнными, фотография загрузилась и видна.

**Негативные сценарии:**

- Отправьте пустую форму. Она остаётся открытой. Видны три сообщения: «Введите название объявления», «Добавьте описание», «Загрузите хотя бы одну фотографию».
- Введите цену 1 000 001 ₽. После попытки публикации появляется сообщение «Цена не должна превышать 1 000 000 ₽».
- Включите «Несколько штук в наличии» и введите 101. После попытки публикации появляется сообщение «Количество не должно превышать 100».
- Откройте `/advertisements/create` гостем. Сайт переводит на `/auth/login`, где виден заголовок «Вход в аккаунт».

В тестах на цену и количество заполните остальные поля верно и приложите фото. Проверьте, что введённые значения остались в форме и запрос на создание не отправился.

### Часть 2. Работа с избранным

**Позитивные сценарии.** Открывайте сайт гостем. Объявления, которые понадобятся тесту, заранее создайте через API от имени продавца.

- Откройте избранное впервые. Видны заголовок «Избранное» и сообщение «В избранном пока пусто», карточек нет.
- В каталоге нажмите сердечко на своей тестовой карточке. Оно стало выбранным. В избранном появилась карточка с теми же названием и ID.
- Добавьте объявление в избранное, откройте избранное и обновите страницу. Карточка осталась в списке, сердечко по-прежнему выбрано.
- Добавьте одно объявление, затем нажмите его сердечко в избранном. Карточка исчезла, список пуст. В каталоге у этого объявления сердечко больше не выбрано.

**Негативный сценарий.**

- Добавьте два объявления в избранное. В поиске по избранному введите слово, которого нет ни в одном названии. Карточек нет, видно сообщение «В избранном пока пусто». Очистите поиск: обе карточки снова видны, у каждой выбрано сердечко.

## Что потребуется

- Ваш форк [web-tests-student](https://github.com/qa-course-avito/web-tests-student) с практики по архитектуре UI-тестов.
- Git, Node.js версии 22.15 или выше и редактор, в котором вы работаете с JavaScript.
- Учебный аккаунт на [Testboard](https://testboard.avito.com/), фотография для объявления и [спецификация API](https://testboard.avito.com/docs/swagger.json) для подготовки и удаления тестовых данных.

## Как выполнять

1. В корне форка выполните `npm ci` и `npx playwright install chromium`. Заполните локальный `.env` по образцу `.env.example`, указав почту и пароль продавца.
2. В ветке `main` добавьте тесты на публикацию в `tests/create`, а на избранное — в `tests/favorites`. Каждый сценарий оформите отдельным тестом.
3. Запустите каждый тест отдельно, затем весь набор командой `npx playwright test --repeat-each=3`. Откройте отчёт командой `npx playwright show-report`.
4. В `README.md` опишите настройку, запуск тестов и просмотр отчёта. Отправьте изменения в `main`. Преподавателю передайте ссылку на форк и SHA проверенного коммита.

> Преподаватель проверит работу в ветке `main` вашего форка.

## Требования к заданию

- Каждый тест проходит отдельно и при трёх повторах подряд. Данные для него создаёт сам тест или его фикстура.
- Сохраните ID сразу после создания объявления. При завершении теста, в том числе после падения, проверьте владельца и удалите только объявления этого теста.
- В Page Object храните локаторы и действия со страницей, в хелперах — запросы к API, в фикстурах — подготовку и очистку. В тесте оставьте шаги пользователя и проверки результата.
- При падении по сообщению проверки должно быть понятно, какое значение ожидалось и что показал интерфейс. Для разбора используйте trace из отчёта Playwright.
- Пароли, токены, сохранённые сессии и результаты прогонов исключите из Git.
