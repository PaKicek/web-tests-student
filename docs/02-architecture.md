# Практика по архитектуре UI тестов

**Статус: для предварительного ознакомления — следующее занятие.** Можно изучить условие заранее. Требования разберём после изучения ООП и архитектуры UI-тестов; выполнять и сдавать эту практику сейчас не требуется. Сейчас выполняйте [первую практику](01-first-test.md).

## Цель

Перенести работающий тест на Page Object, разделить обязанности модулей и добавить два независимых сценария.

Продолжительность занятия — 90 минут. Продолжайте работу **в своём форке web-tests-student**. Перед рефакторингом сохраните успешный первый тест в коммите: это версия, с которой можно сравнить результат.

К началу практики должен быть готов один тест пустой формы с двумя проверками. Понадобятся классы, constructor, наследование и super. В ходе занятия вы разделите локаторы и действия, сценарии, учебные данные и настройки; готовые локаторы и реализацию из эталона копировать не нужно.

## Учебный аккаунт

Подготовьте один действующий аккаунт Testboard. Его логин — email. Скопируйте `.env.example` в локальный `.env`, заполните `E2E_USER_EMAIL` и `E2E_USER_PASSWORD`. Подключите чтение файла в конфигурации Playwright (например, через `process.loadEnvFile` в Node.js 22). Если файла нет, гостевые сценарии должны по-прежнему запускаться. Проверяйте наличие email и пароля при создании авторизованной фикстуры. В Git храните только пустой пример настроек.

## Структура проекта

Создайте модули и перенесите первый тест в tests/practice/login.spec.js:

```text
web-tests-student/
├─ pages/
│  ├─ basePage.js
│  ├─ mainPage.js
│  ├─ loginPopupPage.js
│  └─ profilePage.js
├─ helpers/auth.js
├─ fixtures/auth.fixture.js
├─ configs/
│  └─ environment.js
├─ tests/practice/
│  └─ login.spec.js
├─ package.json
├─ package-lock.json
├─ playwright.config.js
└─ README.md
```

Файлы и реализацию напишите самостоятельно. Удалите прежний tests/empty-login.spec.js после переноса, чтобы одна проверка не запускалась дважды.

## Обязанности модулей

- BasePage хранит page и открывает переданный путь. Для MainPage используйте наследование BasePage и super(page).
- MainPage открывает главную страницу и форму входа.
- LoginPopupPage хранит локаторы формы и выполняет её действия: отправку и переход к регистрации. Основные проверки результата остаются в тестах.
- Helper отправляет `POST /api/v1/auth/login` с JSON `{ email, password }`, проверяет успешный ответ и получает `token` и `user`.
- Тестовая фикстура `authedPage` использует helper и готовит страницу в новом контексте. До первой навигации на Testboard установите состояние через `page.addInitScript` для origin стенда. Testboard читает три ключа localStorage: `auth-storage` (JSON с `{ state: { user, token }, version: 0 }`), `auth_user` (JSON пользователя) и `auth_token` (токен строкой). Откройте главную и передайте страницу тесту через `await use(page)`.
- В Page Object вынесите открытие профиля через меню и локатор email в профиле.
- environment хранит адрес сайта: BASE_URL из переменных окружения или https://testboard.avito.com по умолчанию. Подключите настройку в playwright.config.js.
- tests/practice/login.spec.js описывает сценарии и ожидаемые результаты. В beforeEach гостевой группы можно вынести открытие формы; состояние других тестов использовать нельзя.

## Три теста

1. **Пустая форма.** Перенесите первый тест на Page Object. После отправки проверьте «Email обязателен» и «Пароль обязателен».
2. **Вход через API.** Импортируйте расширенный `test` из файла фикстуры и запросите `authedPage`. Откройте профиль через меню пользователя. С помощью `expect` проверьте, что в профиле виден email именно вашего учебного аккаунта из `E2E_USER_EMAIL`. Ответ 200 подтверждает только подготовку сессии.
3. **Переход к регистрации.** Нажмите ссылку регистрации в форме входа. Проверьте адрес /auth/register и видимый заголовок «Регистрация».

Каждый тест начинает работу в новом контексте браузера. Пустая форма и регистрация используют обычную гостевую `page`. Только тест профиля запрашивает `authedPage`.

## Проверка и сдача

```bash
npm test -- tests/practice
npm test -- tests/practice --repeat-each=3
npm run report
```

Проверьте также запуск каждого сценария отдельно через `npm test -- -g "имя теста"`. В проекте должно остаться три теста практики. Обновите README с описанием модулей и командами, затем передайте преподавателю ссылку на тот же форк и SHA нового коммита.

## Критерии готовности

- Первый сценарий сохранил поведение после рефакторинга.
- Все три теста выполняются независимо и проходят три раза подряд.
- Локаторы и действия находятся в Page Object, а ожидаемые результаты видны в тестах.
- Вход через API использует email и пароль из окружения. Фикстура передаёт авторизованную страницу, а тест проверяет email в интерфейсе профиля.
